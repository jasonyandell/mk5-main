# LEM — Little Expert Model

Can a phone-class open model learn to play Texas 42 by reasoning about it?

## The idea

Take [Gemma 4 E2B](https://huggingface.co/unsloth/gemma-4-E2B-it-GGUF) (~2.3B effective params,
128K context, native thinking channel) — a model that has never heard of Texas 42 — and teach
it to make good in-game decisions via a **backwards curriculum** layered on **STaR-style
self-taught reasoning**. We start at the end of the game, where the lookahead horizon is
shortest and the E[Q] labels are cleanest, and ratchet backward one ply at a time.

The model is never a teacher; it is always the player. We replace a bot mid-game and ask:
can Gemma do at least as well as the bot would have, in expectation?

## North star

> **E[Q] delta vs. the bot it replaced**, measured on a held-out set of seeds, rising over
> training iterations.

If that number goes up, the experiment worked. If it doesn't, we learn something about the
limits of 2B-class reasoning in imperfect-information games. Fun either way.

## Pipeline at a glance

```
┌──────────────────────────────────────────────────────────────────┐
│  STAGE 0 — Rules Adapter                                         │
│  Teach Gemma what Texas 42 *is*.                                 │
│                                                                  │
│  • Rules primer (1-2 pages, manual)                              │
│  • Synthetic Q&A corpus generated by the game engine             │
│    (legal moves, trick winners, count math, void inference, …)  │
│  • LoRA fine-tune via Unsloth                                    │
│  • Gate: parsing sanity check on held-out narrations             │
└──────────────────────────────────────────────────────────────────┘
                             │
                             ▼
┌──────────────────────────────────────────────────────────────────┐
│  STAGE 1 — STaR on Trick-6 Decisions                             │
│  Teach Gemma to reason about a single ply of lookahead.          │
│                                                                  │
│  • Generate games: all 10 declarations × many seeds × 4 seats    │
│  • Narrate each from a narrator's seat                           │
│  • Filter to trick-6 decisions with a real choice + clear gap    │
│  • Upload filtered dataset to HuggingFace                        │
│  • Inference pass: collect thinking traces from rules-adapter    │
│  • Grade: K1 "beat the bot" (E[Q] >= bot's E[Q])                 │
│  • On success → keep trace. On failure → rationalization (R1)    │
│  • LoRA step on kept traces                                      │
│  • Iterate until E[Q] delta plateaus                             │
└──────────────────────────────────────────────────────────────────┘
                             │
                             ▼
┌──────────────────────────────────────────────────────────────────┐
│  STAGE 2+ — Widen the curriculum backward                        │
│  Trick 5, then 4, then 3 … each stage = one more ply of          │
│  lookahead. "Last K non-forced decisions for the narrator."      │
└──────────────────────────────────────────────────────────────────┘
```

## Design choices we've committed to

| Choice | Value | Why |
|---|---|---|
| Base model | Gemma 4 E2B | Phone-class, Apache 2.0, native thinking channel |
| Narrator framing | "You are taking over for a bot" | Gives natural voice + baseline + realistic state distribution |
| Game gen policy | E[Q] greedy, N=10 | Verified during zeb — not much worse than N=100 and way cheaper |
| Bidder | Existing (broken) bidder | Reasonable-not-great is fine; we want plausible states, not optimal play |
| Declaration coverage | All 10 per seed | Balanced trump coverage by construction |
| Perspectives per game | All 4 | Free 4× on data; **split train/val by seed**, not by narration |
| Decision filter | Trick 6, `|legal| ≥ 2`, non-trivial E[Q] gap, bounded SEM | Short horizon = clean labels; forced/coinflip decisions = no learnable signal |
| Keep rule | **K1**: keep iff `E[Q][gemma] ≥ E[Q][bot]` | Matches the relief-pitcher framing; self-sharpens as Gemma improves |
| Failure handling | **R1** STaR rationalization: reveal bot's action, ask Gemma to justify it, keep that rationale | Simpler than DPO; proven in the STaR paper |
| Fine-tune method | LoRA via Unsloth | Only sane option on 3050 Ti; Unsloth has a Gemma 4 recipe ready |
| Dataset home | HuggingFace | Shared artifact between local, Vast, and Modal compute |
| Variance handling | Filter out, don't correct | Refuse to train on states where strategy doesn't exist |

## Compute menu

- **3050 Ti (local)** — narration generation, parsing checks, interactive LoRA iteration, small runs. Free and fast-feedback.
- **Vast.ai** — spawn a 3090/4090 when a training run gets too long. Pennies per experiment.
- **Modal ($30 free credit)** — burstable parallel work (mass Q&A generation, mass inference passes).
- **HuggingFace** — shared dataset + adapter store across all of the above.

## The gaps we're deliberately leaving open

Things we'll decide once we have more information, not now:

- **Exact variance filter thresholds** (`δ`, `σ_max`) — start permissive, tighten from wandb.
- **Stage 0 corpus size and category mix** — depends on the parsing sanity check result.
- **Whether the rules primer stays in the system prompt forever** or gets distilled into the
  weights and removed.
- **When to ratchet** — Stage 2 only begins once Stage 1 has clearly plateaued.
- **Whether rationalization (R1) is enough** or we eventually need DPO-style preference
  learning for Stage 3+.
- **Training hyperparameters** — LoRA rank, LR, epochs. Defaults from Unsloth's Gemma 4
  recipe, adjust based on what wandb shows.

## Non-goals

- Beating the full-info Stage 1 oracle. (Impossible; it sees all four hands.)
- Beating the existing bot *in game outcomes*. (We're measuring E[Q] delta, not win rate —
  luck washes out in aggregate but not in any single game.)
- Training a general-purpose 42 explainer, commentator, or rules tutor. (The rules adapter
  is a means, not an end. Though if it turns out useful, we'll push it to HF anyway.)
- Matching perfect play. We want *learning*, not optimality.

## What makes this interesting regardless of outcome

1. **The backwards curriculum is clean.** Each stage literally adds one ply of lookahead.
   Most curriculum learning hand-waves about "difficulty"; here difficulty is a counted
   quantity.
2. **The rules adapter is self-verifying.** The game engine generates ground truth, so
   there's no hallucination risk in the training corpus.
3. **The relief-pitcher framing gives us a living baseline.** As Gemma improves, K1 gets
   harder on its own. The experiment self-adjusts.
4. **Negative results are publishable.** "Gemma 4 E2B learns trick-6 reasoning but fails to
   learn trick-4 reasoning" tells us something real about where small-model reasoning
   breaks down on imperfect-information games.

## Progress log

### Stage 0 v1 complete (2026-04-10)

**What we built:**
- Narration generator (`lem/narrate/`) — plays a game via E[Q] N=10, renders second-person
  prose, truncates at any narrator turn for STaR prompts. Forced-play annotations prevent
  hallucinated strategy on non-choices. Running score kept (input to reasoning).
- Rules primer (`lem/rules/primer.md`) — 1549 words, straight tournament 42 only.
  55/55 committed facts verified against the engine (`lem/rules/verify_primer.py`).
- Q&A corpus (`lem/rules/generate_qa.py`) — 3500 examples across 7 categories:
  trump membership, led suit, legal moves, trick winners, count math, hand tracking,
  void inference. All engine ground truth.
- Stage 0 LoRA adapter trained on Modal L4, pushed to HuggingFace at
  `jasonyandell/gemma-4-e2b-texas42-stage0`.
- Wandb: `jasonyandell-forge42/lem-stage0`.

**Training recipe that works (save yourself the 5 failed attempts):**
1. Monkey-patch `Gemma4ClippableLinear` to inherit from `nn.Linear` before loading.
   See `train_stage0.py` or https://huggingface.co/google/gemma-4-31B/discussions/3
2. Use `bf16` (not fp16 — GradScaler fails with gradient checkpointing).
3. Use `gradient_checkpointing=True` with `use_reentrant=False` (model is ~20GB in bf16,
   L4 has 22GB — no room for activations without checkpointing).
4. Skip eval (`eval_strategy="no"`) — eval forward pass OOMs on L4. Training converges
   to 100% accuracy by step 50; eval is redundant.
5. 1 epoch is plenty. Loss goes 32 → 15 → 2.8 → 0.001 in 40 steps.

**First contact vs second contact (same prompt, seed 42, fives trump, trick 6):**

| Dimension | Base Gemma | + Stage 0 adapter |
|---|---|---|
| Hand tracking | Confused initial/remaining hand; played 5-5 (already gone) | Correctly read "remaining: 6-2, 6-1" |
| Final answer | "Play 5-5" — **illegal** | "Sluff 6-2 or 6-1" — **legal, correct** |
| Trump membership | Called 6-4 a trump under fives | Still calls 4-4, 6-4 trumps (same error) |
| Reasoning | Good structure, wrong state | Better structure, correct state |

**Key insight:** Trump membership didn't transfer from Q&A format to narration-context
reasoning. But that's exactly the kind of thing you learn by playing more games and getting
corrected — which is what Stage 1 (STaR) does. Humans learn trump rules the same way:
not from flashcards, but from playing hands and getting it wrong until it clicks.

### Next: Stage 1 — STaR on trick-6 decisions

The adapter is good enough to start. STaR's K1 grading ("beat the bot") will naturally
penalize trump errors when they cause bad plays, and rationalization will teach the model
why the bot's move was better. The remaining rule gaps will close through practice, not
drilling.

**Concrete next steps:**
1. Generate narration dataset in batch mode (all decls × many seeds × 4 perspectives).
2. Filter to trick-6, |legal| >= 2, non-trivial E[Q] gap. Upload to HuggingFace.
3. Build STaR harness: inference → grade (K1) → rationalize failures (R1) → LoRA step.
4. Run first STaR iteration, measure E[Q] delta on held-out seeds.
5. Obsess over wandb.
