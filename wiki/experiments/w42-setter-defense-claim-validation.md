## Summary

[[w42]] now has a report-only setter-defense validation slice for `t42-csw6.20`.
It tests Chapter 5 and related Chapter 12 setter-defense claims against the
available public/action-local v0 strategy tags and stored [[forge]] E[Q] labels.

The original headline was conservative: this run did not move any central
claim-ledger status, because the v0 artifacts lacked direct setter-role,
bidder-off, void-creation, trump-set, and bid-margin/set-threshold detectors.
The proxy evidence was still useful because it showed that naive
opponent-currently-winning count donation was high-regret outside a properly
gated setter-pounce detector.

The follow-up [[w42-gus-corpus-tactical-claim-deep-dive]] supersedes the pounce
part of that limitation for the Gus v2 generated-corpus slice. It implements
role-gated pounce-count labels over 28,000 decisions and finds that pounce count
beats same-decision alternatives by about +4.1 Q, while reckless count into the
bidder side is about -8.4 Q. Other Chapter 5 families on this page remain
underpowered or untested.

[[w42-tactical-claim-replication]] confirms that result with a full legal-action
row export and reusable harness output. The replication keeps pounce count at
`+4.102` Q versus same-decision alternatives, pounce count that sets now at
`+6.069`, and reckless count at `-8.372`. It also adds declaration/seat/trick
and count-amount slices for follow-up work, while leaving broad Chapter 5 status
movement conservative.

## Key Question

Can the existing w42 v0 public/action-local tags validate setter-defense claims
from [[winning42-ch05-setter-defense]] and related
[[winning42-ch12-advanced-bidding-playing]] pounce claims, using oracle regret and
bucket analysis where possible?

## Method

| field | value |
|---|---|
| report owner bead | `t42-csw6.20` |
| evidence mode | report-only validation script over existing Gus-format eval corpus with forge E[Q] labels |
| ruleset / score mode | existing Gus corpus semantics |
| decision slice | all 560 eval decisions; setter-defense proxies only |
| train/eval split policy | inherited w42 eval-only corpus, `gus/data/corpus_eval_20.pt` |
| statistical test | candidate-action regret and paired best-proxy regret with bootstrap 95% intervals |
| success criterion | claim-specific status movement only if a direct detector is present and paired regret supports a narrow claim |

The script loads `JointWorldFullDataset(..., include_strategy_features=True)` and
uses only v0 public/action-local tags plus stored `e_q` values. It does not train a
model, generate games, modify [[gus]] core paths, or change forge oracle semantics.

## Findings

| finding | evidence | metric | status |
|---|---|---|---|
| Current v0 tags cannot directly validate setter-pounce claims. | `missing_detectors.csv` | missing `bidder_off_window`, `points_needed_to_set`, setter role, void/pounce attribution | not-yet-tested |
| Naive count into opponent-currently-winning windows is bad without setter-pounce gating. | `claim_proxy_stats.csv` | paired regret +5.111 for count vs non-count, CI `[2.279, 8.039]`, n=52 | underpowered proxy evidence |
| Ten-count pounce proxy is also high-regret without bid-margin/set-threshold gates. | `claim_proxy_stats.csv` | paired regret +4.353, CI `[1.544, 7.628]`, n=4 | underpowered proxy evidence |
| Count-calling lead and count-protection proxies are too broad for claim movement. | `claim_proxy_stats.csv` | count-calling paired CI crosses zero; protection proxy measures protected count actions, not protector-preserving discards | underpowered |
| Trump-set detection remains unmeasured. | `missing_detectors.csv` | no `trump_set_signal`, `trump_rich_defender`, or partner-recognition detector in v0 artifacts | not-yet-tested |

## Caveats

- The run is a proxy report over 560 eval decisions, not a direct
  setter-defense detector implementation.
- The current v0 tag surface does not identify bidder seat, setter role,
  bidder-off exposure, high-bid bucket, partner hidden winner, bid margin, or
  points needed to set.
- Positive paired regret deltas for count-to-opponent proxies should not be read
  as contradiction of the book's setter-pounce claim; they mostly show why the
  direct pounce gate matters.
- No fresh game generation, model training, HF upload, or central claim-ledger
  status update was performed.
- W&B was live and recorded the script run plus generated artifacts.
