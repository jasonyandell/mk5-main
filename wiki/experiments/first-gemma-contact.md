## Summary

A single inference pass run against [[gemma-4-e2b]] (Gemma 4 E2B, fp16, L4 GPU via [[modal]]) to test whether a phone-class model produces coherent reasoning about [[texas-42]] when primed with rules and a narrated game state. Not a training run. Zero training data collected. Purely a sanity check on the premise before committing to the full [[lem]] pipeline.

([lem/gemma_star/modal_app.py @ a8bccfa](../sources/a8bccfa.md))

## Setup

A [[narration]] of a game in progress was generated by `lem/narrate/` using the E[Q] greedy policy (N=10) from [[forge]]'s GPU pipeline, truncated at a narrator turn via `--stop-at-narrator-turn K`. The [[rules-adapter]] primer (`lem/rules/primer.md`, 1549 words) was prepended via `--with-primer`. The combined prompt was passed to Gemma 4 E2B with thinking mode enabled (`enable_thinking=True` in the chat template).

Modal function details:
- Model: `google/gemma-4-E2B-it`, loaded in `torch.float16`
- GPU: L4
- Max new tokens: 2048
- Temperature: 0.6
- Model weights cached in a Modal volume across invocations

## Result

> model correctly identified trump, led suit, void status, and score math — but confused initial hand with remaining hand and misclassified 6-4 as trump under fives-trump. Exactly the gaps Stage 0 should close.

— commit message, a8bccfa

**Correct:**
- Trump identification
- Led suit determination
- Void status inference
- Score math

**Wrong:**
- Confused the initial (full) hand with the remaining (partially played) hand
- Misclassified 6-4 as trump when fives are trump (6-4 is not a five; it is only trump when fours or sixes are trump)

## Significance

The errors map precisely onto what [[rules-adapter]] (Stage 0) is designed to fix: the Q&A corpus will include legal-move checks, trump membership queries, and hand-state disambiguation. The result justifies the two-stage plan in [[lem]] ([lem/OVERVIEW.md @ a8bccfa](../sources/a8bccfa.md)).

This contact also motivates the "Facts this primer commits to" section of `lem/rules/primer.md` as a self-verifying ground truth for [[rules-adapter]] training and eval.

## Scope boundaries

- Single inference pass only; no loop, no grading, no LoRA update
- No [[k1-grading]] or [[r1-rationalization]] applied
- No [[expected-q-value]] delta computed — this is not a [[backwards-curriculum]] step
- No [[lora-unsloth]] fine-tuning triggered
