## Summary

[[w42]] uses a forge-style report template for model runs, detector checks, and
strategy-claim validation. The template borrows the report discipline from
[[forge-analysis]]: explicit epistemic status, a narrow key question, reproducible
method, visible baselines, concrete findings, caveats, generated artifacts, and
next checks.

This page is template-only. It does not run an experiment, create a dataset,
upload an artifact, or test a Winning 42 claim.

Reusable w42 template:

- `w42/report_template.md`

W&B links: not applicable.

HF links: not applicable.

Claim ledger impact: no claim-ledger change.

## When To Use

Use this template for w42 work that produces one or more of:

- a model run comparing raw public state, cheap strategy tags, richer
  chapter-derived tags, or concept buckets;
- a detector validation report for a Winning 42 concept;
- a claim-ledger evidence update using enumeration, [[forge]] oracle output,
  [[gus]] or w42 probes, or [[burl]] trace review;
- a negative or underpowered result that should be preserved for future beads.

Do not use the template as evidence by itself. A filled report may update the
claim ledger only when the report names the tested claim, data slice, method,
artifact, and status delta.

## Adaptation Notes

The template keeps the section rhythm used by
`forge/analysis/report/13_statistical_rigor.md` and
`forge/analysis/report/26_austin_verification.md`: key question, method,
findings, interpretation, caveats, and generated files. w42 adds the pieces that
make strategy-claim validation safe:

- the [[w42-dataset-manifest]] table comes before findings so the data slice is
  visible before any conclusion;
- the feature/detector table records whether each signal is public-state safe;
- baselines must include `E[Q] N=10` when the report is a policy/model comparison;
- concept buckets make count donation, trump pressure, pounce windows, 84
  preservation, and endgame walkers first-class report slices;
- claim-ledger impact is explicit even when the answer is `no claim-ledger change`;
- W&B and HF links stay in the report, but use `not applicable` until a real run
  or artifact exists.
