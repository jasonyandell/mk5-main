> feat(lem): public state block after every trick — played dominoes, count status, hand
>
> A 2B model shouldn't reconstruct game state from prose any more than a
> human should memorize 28 dominoes. In real 42, this information is public
> and visible at the table. Some variants even exploit the difficulty of
> tracking it (stacking on 84 bids).
>
> State block after each trick shows:
> - All dominoes played so far (N/28)
> - Count domino status (taken by which team, or still out)
> - Narrator's remaining hand
>
> ~60 tokens per trick, ~300 extra per prompt. Tiny cost for a massive
> reduction in the bookkeeping burden on the model.

## Key implementation details

`_render_state_block()` produces three lines:
1. `Played so far (N/28): <domino list>` — all dominoes played in order
2. `Counts taken: <dom(pts)→team, ...> | still out: <dom(pts), ...>` — count-domino disposition
3. `Your hand: <remaining hand>` — narrator's current hand

The block is appended after every full trick result line and also at the decision point (where the narrator is asked "What do you play?"). State is tracked incrementally in the renderer loop rather than recomputed per trick.

Also fixes the prior hand-tracking logic in the decision block: the old approach recomputed the narrator's remaining hand by scanning all past decisions; the new approach maintains `narrator_remaining` as a shrinking list throughout the render pass.

## Significance

All information in the state block is public — visible to every player at a real Texas 42 table. The decision encoded in [[public-state-block]]: narrators provide public state; models spend capacity on strategy.
