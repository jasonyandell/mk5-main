## Two bugs, one root cause

Both bugs caused the eval to extract and grade corrupted text (prompt fragments, partial inputs) instead of the model's actual response. All eval results from [[4729dad]] were invalid as a result.

**Bug 1 — EOS token mismatch:** `generate()` was configured to stop on token 1 (`<eos>`). Gemma 4 uses token 106 (`<turn|>`) to signal end-of-turn in its chat template. Without token 106 in `eos_token_id`, generation continued past the model's intended response end, appending padding or truncating incorrectly.

**Bug 2 — Left-pad slicing:** to separate input from generated output, the code used `attention_mask.sum()` — the count of real (non-padding) tokens. With left-padding, padding precedes the real input, so real tokens appear at the END of `input_ids`. Using `attention_mask.sum()` as a slice offset from the start included trailing real input tokens in the "response." Fix: use `input_ids.shape[1]` (the full padded input length) as the split point.

## State after fix

Clean responses extracted, but a new issue surfaces: the adapter-trained model still says "This is a game of Bridge" and reasons from scratch. The LoRA adapter changes training loss but does not override base model behavior at generation time with 4 epochs. Resolution: more epochs + thinking mode disabled. See [[3c33e86]].
