> feat(lem): scratchpad validation — only train on factually-correct traces
>
> The model now fills a structured scratchpad (HAND/VOIDS/COUNTS/PLAY) before
> deciding. Each claim is validated against engine ground truth:
> - HAND must match remaining dominoes exactly
> - COUNTS must correctly track which count dominoes are played/out
> - PLAY must be legal
>
> Only traces with correct facts get trained on. This prevents the model from
> learning hallucinated game-facts that happen to produce correct moves.
>
> New grading categories: valid_pass (gold), valid_fail (rationalize),
> invalid (discard — wrong facts), illegal (discard), parse_fail (discard).
>
> Also: different random subset of examples per iteration (--subset N),
> enriched narrations v2 format with ground truth fields.

## Validation rules

Three checks against engine ground truth:
1. HAND must match the remaining (not initial) dominoes exactly
2. COUNTS must correctly identify which count dominoes have been played/are out
3. PLAY must be legal given the current game state

## Grading categories

| Grade | Meaning | Action |
|---|---|---|
| `valid_pass` | Facts correct + beat bot | Keep as training trace |
| `valid_fail` | Facts correct + legal but suboptimal | Rationalize |
| `invalid` | Any scratchpad fact wrong | Discard |
| `illegal` | Play not in legal set | Discard |
| `parse_fail` | Cannot extract play | Discard |
